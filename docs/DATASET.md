# Dataset

The detector's training data was assembled by merging and cleaning five public
warehouse/logistics datasets into a single two-class corpus. This document records
the sources, the cleaning steps, and the final composition.

## Scope: two classes

Only `person` and `forklift` are kept. PPE, pallet, and rack classes were collected
but dropped — they never enter the downstream risk model, and partially-annotated
extra classes would hurt the detector without adding value.

## Sources

Five datasets were merged (LOCO and other logistics/warehouse/forklift/worker
sources). Each used different class names, index orders, and annotation formats.

## Cleaning pipeline

| Step | What & why |
|---|---|
| Class standardisation | Every source's classes remapped to `person`/`forklift`; all else dropped. |
| Name-based remapping | Classes mapped by **name** read from each `data.yaml`, not by index — an earlier index-based approach silently mislabelled one source's `small_load_carrier` (index 3) as `person`. Caught by visualising labels on sample images. |
| Perceptual-hash dedup | Roboflow datasets are heavily re-forked; **8,767 duplicate images** removed before splitting, so the same scene cannot land in both train and validation (which would inflate reported mAP). |
| Polygon → box | 945 segmentation-polygon labels converted to YOLO detection boxes. |
| Validation pass | Every label checked for missing files, corrupt images, invalid classes, and malformed boxes — driven to zero. |

## Final composition

- 23,778 images
- ~65,000 person instances, ~8,600 forklift instances (≈7.6 : 1)

The class imbalance is expected — people are far more common in the footage than
forklifts — and the forklift metric (mAP@50 = 0.94) is tracked specifically because
it is the rarer, safety-critical class.

## Note on conflict data

This dataset trains **detection** only. Forklift–pedestrian *conflict* data cannot
be safely collected from the real world, so conflict scenarios for the risk model
are generated by the procedural simulator (see `ARCHITECTURE.md`, stage 6).
